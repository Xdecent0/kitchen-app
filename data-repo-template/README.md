# kitchen-data — шаблон приватного репозитория

Это заготовка второго репозитория для приложения «Кухня». Здесь живут твои данные; в публичном `kitchen-app` — только код.

## Как развернуть

1. Создай на GitHub **приватный** репозиторий, например `kitchen-data`.
2. Скопируй в него содержимое этой папки: `.github/`, `scripts/`, и пустые папки `Состояние/`, `Чеки/`, `Задания/вход/`, `Задания/выход/`.
3. Положи туда же справочники и рецепты из волта — папку `30 - Личное/Кухня/Справочники/` и файлы рецептов.
4. Сделай ключ доступа: **Settings → Developer settings → Personal access tokens → Fine-grained tokens**. Доступ — только к этому репозиторию, права — **Contents: Read and write**.
5. В приложении открой «Настройки», впиши `логин/kitchen-data` и вставь ключ.

Ключ создаёшь и вставляешь только ты сам. Он хранится в браузере устройства и никуда больше не уходит.

## Что делает workflow

Браузер не может ходить на чужие домены. Поэтому приложение кладёт задание в `Задания/вход/`, workflow просыпается по push, ходит наружу и пишет ответ в `Задания/выход/`. Круг занимает около полминуты.

| Вид задания | Что делает |
|---|---|
| `receipt-qr` | идёт по ссылке из QR фискального чека и вытаскивает позиции |
| `receipt-ocr` | прогоняет фото чека через Tesseract |
| `import-recipe` | тащит рецепт со страницы: сначала schema.org, потом разбор вёрстки |

Ошибки не глотаются — они возвращаются в файле ответа, и приложение показывает их текстом.

## Второй человек

Добавь его коллаборатором этого репозитория (Settings → Collaborators). Он ставит приложение по той же ссылке и вводит **свой** ключ. Отметки в списке сливаются по каждой позиции отдельно, так что двое в магазине не затирают друг друга.

## Структура

```
Состояние/     склад, список, правила, расход, меню, трекинг, магазины
Чеки/          разобранные чеки
Рецепты/       markdown-заметки, редактируются в Obsidian
Справочники/   сроки, синонимы, отделы
Задания/       вход и выход для GitHub Actions
```
